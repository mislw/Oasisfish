# Agent Note: 桌面端共享 Harness 启动

Status: implemented

[English](2026-09-08-desktop-shared-harness-startup.md) | 中文

## 问题

安装版和解包版 Oasisfish 共用同一个桌面用户数据目录。Electron 应用锁无法协调从不同可执行文件位置启动的进程，因此两个发行目录可能并发启动 Harness，并在重新指向同一批 profile 模块回退链接时发生竞争。失败的一方会在 HTTP 就绪前退出，桌面外壳随后报告启动失败。

## 决策

桌面用户数据目录持有唯一 Harness 启动协调器。只有当 `desktop-ready.json` 指向仍存活的 PID、HTTP `127.0.0.1` URL 且请求成功时才会复用。否则某个桌面进程会原子创建 `desktop-harness-startup.lock`，再次检查就绪状态，并在持锁期间启动 Harness。其他发行目录等待就绪，不会再启动一个进程。锁所有者缺失、无效或已退出时，恢复流程会先移除陈旧锁再重试。

Harness 启动还会通过 `$DSH_HOME/profiles/.module-fallback-heal.lock` 串行执行 `healProfilesModuleFallback` 本身。这把锁覆盖完整的依赖遍历和每一个回退链接更新，因此桌面协调器以外的调用方也无法把不同安装目录的链接交错写入。仍存活的所有者会被等待；已退出的所有者仅在 inode 与记录仍匹配时移除；无效锁和所有权替换会直接失败，而不会删除观察到的路径。

打包安装切换完整 fallback 时，Windows 可能持续占用大量已移动或删除的 junction 名称。因此修复器会在持有修复锁期间先在同级目录生成全部链接，再通过一次目录改名发布。生成链接集合之前，它会把安装锚点和每个发现的包解析到真实目录；否则 workspace 或 pnpm junction 可能成为另一层 junction 的目标，Windows 会把结果折叠成目标设备不可用的挂载点。发布失败时恢复旧目录。清理通过父目录枚举判断条目类型，不跟随链接目标，因此即使陈旧 junction 的目标设备不可用也能替换。它只接受 junction 以及仅包含 junction 的 scope 目录；如果 Windows 仍占用旧目录，则保留可识别的退役目录。

桌面进程分别记录启动所有权和复用结果。只有该进程自己启动的 Harness 才会写入 `harnessProcess`，并在退出或安装更新时被终止。复用其他进程 Harness 的窗口不会将其杀掉。

## 考虑过的替代方案

**只依赖 Electron `requestSingleInstanceLock()`。** 可执行文件位置不同会使它无法成为安装版和解包版所需的用户数据目录级权威。

**让每次 profile 链接更新都容忍并发写入不同目标。** 两个安装目录可能包含不同 Harness 版本，接受任意获胜目标会让其中一个运行进程从另一个发行目录解析依赖。

**为每个发行目录分配独立用户数据目录。** 这会通过复制设置、凭据、会话和缓存来规避竞争，违背 Oasisfish 升级和便携使用时保留同一份用户状态的预期。

## 后果

- 共用一个用户数据目录的多个 Oasisfish 发行目录会复用同一个可响应 Harness；即使不经过桌面协调器，每个调用方也会串行修改 profile 模块回退。
- 在不同安装目录之间切换时，可以容忍有界的 Windows junction 删除延迟，同时不会接受外来占用。
- 陈旧就绪文件和启动锁可以恢复，无需删除用户配置。
- 被复用 Harness 的生命周期属于启动它的进程；关闭借用窗口不会终止共享工作。
- 协调器只接受仍存活的本机回环 HTTP 端点，因此外部就绪文件无法把桌面窗口重定向到其他地址。
