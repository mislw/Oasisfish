# Agent Note：游戏 UI 工具箱会话

状态：已实现

[English](2026-08-28-game-ui-toolbox-session.md) | 中文

## 问题

通用会话界面会同时暴露所有可用工作流。Oasis UI 生产具有有序评审流程，而专注生图应在图片生成并确认后结束。两者都要求加载 `oasis-wiki` Skill 并持久记录进度。只存在于前端的向导会在重启后丢失状态，也可能与模型可见的会话历史产生分歧。

## 决策

侧边栏提供会话/工具箱切换和通用 `sidebar.toolbox` slot。Oasis UI 工具会创建或恢复专用的 `game-ui` Agent Preset 会话。该 preset 持有允许使用的工具，要求加载 `oasis-wiki`，通过 `todo_write` 建立固定的八阶段工作流，并要求每次推进前使用 `ask_user_question` 取得确认。

“纯生图”工具会创建或恢复独立的 `game-image` Agent Preset 会话。它建立“需求、规格、生成、确认”四个固定阶段，工具清单仅包含 Skill 加载、todo 进度、关键问题询问和 `image_generate`。它使用模型设置中配置的默认生图模型，不包含文件系统、Shell、UI 重建、UMG、Lua 或编辑器写入工具。

客户端把持久化的 `todos` 投影作为首版阶段记录。每个 preset 提供自己的有序阶段列表，客户端在 `conversation.session.header.progress` 和 `conversation.details.summary` 中显示对应投影；页头进度可以打开现有详情栏。启动空白专用会话时发送该工具的一次性启动提示词，恢复已有会话时不发送任何内容。Lua、配置表和日志工具会保持禁用，直到各自拥有真实组装工作流和验收证据。

## 结果

工作流可以从会话日志重建，并在应用重启后继续，不需要第二套前端持久化模型。每个专用 preset 都会限制模型的工具清单，并使无关请求留在对应会话之外。生图能力可以复用默认生图供应商，同时不继承完整 UI 生产流程。通用侧栏与会话 slot 可以承载后续工具链，无需让这些外壳包理解 Oasis 专属行为。

使用 `todos` 会让可见阶段依赖各 preset 的固定顺序。未来可编辑或可分支的工具链需要专用持久化事件与投影，不能继续复用 todo 文本。

## 考虑过的替代方案

- **只存在于前端的向导**：拒绝，因为进度对模型不可见，也无法从会话日志重建。
- **普通会话中的模式标记**：拒绝，因为通用工具清单和无关历史仍会保持活动。
- **首版就建立通用工具链定义服务**：延后，等待第二条真实工作流提供共享编辑与分支需求。
