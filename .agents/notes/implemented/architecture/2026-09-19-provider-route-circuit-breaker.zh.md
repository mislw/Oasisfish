# Agent Note: Provider-route circuit breaker

Status: implemented

[English](2026-09-19-provider-route-circuit-breaker.md) | 中文

## 问题

提供方重试可以恢复单个 agent（智能体）步骤，但连续的暂时性失败仍可能不断向同一条不可用提供方路由发送物理请求。无界重试策略会让这种压力无限持续，而直接调用 `ctx.llm.stream()` 的消费方不会经过 agent 步骤恢复边界。harness 需要一项准入策略，在不把提供方健康状态移入 agent loop 或持久 Session 数据的前提下，保护发往精确提供方路由的每次物理请求。

请求重叠时，该策略仍必须保持正确。路由关闭时获准的请求，可能在另一个请求已经打开或恢复熔断器后才结束；打开时长结束后同时到达的请求也不能全部成为恢复探测。

## 决策

`@deepseek-ai/dsh-llm-circuit-breaker` 是一个 `llm/stream` 函数插件，按精确的 `GenerateOptions.provider` 值维护进程内状态。`base` 与 `sdk-minimal` bundle 在 `llm-retry` 前启用它。状态由一个 Host 进程内的 Session 与 Agent 共享，并在插件重载或进程重启时丢弃；它不会写入 Session 日志，也不会跨进程协调。

每次获准的物理提供方调用都会贡献一个终止结果。已配置的暂时性失败会增加关闭熔断器的连续计数，成功 finish 会重置计数，达到阈值时只打开对应路由。打开期间的调用返回一条 code 为 `CIRCUIT_OPEN` 的合成终止失败，不执行提供方 I/O。`CIRCUIT_OPEN` 是准入决定而不是提供方健康证据，因此 `dsh-llm-retry` 在 normal 与 always mode 中都把它视为终态。超时与重试继续由各自策略负责。

打开时长结束后，准入会在调用下游前同步预留一个半开探测。并发请求会看到该预留并继续被拒绝。成功或确定性错误的探测会关闭熔断器；已配置的暂时性失败会让它再打开一个完整时长。中止、抛出或未完整结束的探测会释放预留，使后续请求可以再次探测。

每个关闭 generation 与半开 probe 都有不透明标识。只有捕获的标识仍拥有该路由时，终止结果才能改变状态，因此旧状态下获准请求的迟到完成无法关闭、延长或重新打开当前熔断器。同一个插件拥有状态以及改变状态的全部观察，因此本包不发布 `./invariant` 伴生入口。

## 验证

状态机测试覆盖配置拒绝、路由隔离、连续失败重置、打开拒绝、单探测并发、探测结果、中止与未完整流、同步抛出、过期关闭 generation、过期 probe 完成、日志与释放。包源码达到 100% statement、branch、function 与 line coverage。

Loader 组合测试挂载真实 `LlmRuntime`，验证包导出形式，并证明释放插件会同时移除监听器与状态。bundle 测试和构建后的 `sdk-minimal` 清单固定默认组合。无密钥录制 Session fixture 包含两次物理 `SERVER` 尝试，随后以合成 `CIRCUIT_OPEN` 结算，且没有第三次提供方响应；其聚焦 runner 当前被相邻 snapshot 场景同样遇到的既有 built-plane 激活警告阻断。

## 考虑过的替代方案

**把熔断状态放入 `LlmRuntime`。** 拒绝采用，因为提供方健康属于可选部署策略，不是提供方无关服务定义的一部分。插件可以通过现有 `llm/stream` 扩展点同时覆盖 agent 与直接流调用方。

**统计逻辑轮次或重试链。** 拒绝采用，因为受保护的资源是提供方流量。每次物理尝试都有独立结果，包括重试策略创建的尝试。

**持久化或分布式熔断状态。** 拒绝采用，因为首个实现不需要 schema 迁移、外部协调或分布式健康状态的过期协调。Host 重启与插件重载会有意重置策略。

**等待期结束后允许每个请求探测。** 拒绝采用，因为同步恢复流量会抵消打开时长的作用。一个同步预留可在恢复情况未明时限制提供方流量。

**让 always retry 处理 `CIRCUIT_OPEN`。** 拒绝采用，因为这会围绕准入决定形成本地重试循环，并可能在不执行提供方 I/O 的情况下反复消耗 agent 步骤恢复。

## 影响

- 连续暂时性失败会停止一个 Host 内所有 Session 与 Agent 的提供方流量，直接调用 `ctx.llm.stream()` 的消费方也获得相同保护。
- 路由按精确提供方 id 隔离；一条不健康路由不会阻塞另一条路由。
- 打开状态拒绝不消耗提供方 token，也不增加模型输入，但用户与 Session 历史仍会通过现有结算路径收到稳定的终止失败。
- 进程重启、插件重载和多进程部署会丢失或分割健康历史。需要协调熔断状态的部署必须引入独立服务和新的决策。
- 插件实例内的全部路由使用同一项全局策略。不提供逐路由阈值、手动重置、状态检查或故障转移。
