# Agent Note: 自定义模型推理强度

Status: implemented

[English](2026-08-28-custom-model-reasoning-effort.md) | 中文

## 问题

OpenAI-compatible 模型列表通常只返回模型标识，不会声明每个模型接受哪些推理强度。即使请求层和适配器层已经支持按会话选择推理强度，中转站模型也无法在对话选择器中显示对应控件。

## 决策

“模型与中转站”编辑器在每条 pi-ai 模型行上公开推理能力配置。用户勾选该精确模型和中转站接受的标准标识：`off`、`minimal`、`low`、`medium`、`high`、`xhigh` 或 `max`。编辑器把选择存入该模型的 `reasoningEfforts` 映射；新勾选的档位使用标识本身作为 wire 值，`off` 则保存为不带值的条目。

对话模型菜单继续由能力数据驱动。只有所选模型声明了档位时，它才显示“推理强度”一行，并把选择的标识持久化为会话请求配置。全部不勾选会保留未声明能力的状态并隐藏该行，不根据模型名称或提供方协议猜测。

已有的手写 wire 别名在对应档位保持勾选时不会改变。用户取消勾选该档位时，复选框编辑器才会删除别名；创建自定义别名仍需编辑 `settings.yaml`。

## 考虑过的替代方案

**为整个提供方配置一套推理档位。** 中转站提供方通常混合 GPT、Claude、Gemini、生图模型和不支持推理的模型。提供方级声明会为部分模型公布无效选项，或隐藏其他模型的有效选项。

**为每个中转站模型显示全部标准档位。** 模型列表端点无法证明支持情况，发送凭空添加的档位会把配置缺失变成提供方请求失败。

**根据模型标识推断能力。** 中转站前缀与重命名模型由部署决定，名称匹配会过期，也无法证明其接受的 wire 拼写。

## 后果

- 对显式配置的中转站模型，输入框会显示“模型”和“推理强度”两行菜单。
- 同一提供方下的不同模型可以公布不同档位集合。
- 从上游获取模型仍只采纳端点实际返回的事实；用户在模型高级设置中补充推理档位。
- 适配器继续在提供方 I/O 前拒绝不属于精确模型声明集合的档位；若中转站实际未实现已声明的 wire 值，它仍可能拒绝请求。
