# Agent Note：提供方探针最小输出上限

Status: implemented

[English](2026-09-07-provider-probe-minimum-output.md) | 中文

## 问题

提供方连接探针最多请求八个输出 token。部分 OpenAI 兼容中转站会在运行所选模型之前拒绝低于十六 token 的请求，因此有效路由上的所有文本模型都会显示为返回不可用响应。同一项文本探针还会提供明确的 `gpt-image-*` 模型，尽管这些模型使用 Images API 而不是文本生成端点。

## 决策

pi-ai 提供方探针最多请求十六个输出 token。请求仍然是最小的 `Reply with exactly OK.` 生成，但能够满足强制要求十六 token 下限的中转站。

“模型与中转站”页会从文本探针选择器中排除明确的 `gpt-image-*` 纯生图模型 ID，并说明这些模型通过单独配置的生图路由验证。其他模型继续保留，因为能够生成图片的模型也可能支持文本，而模型目录尚未提供与提供方无关的纯生图能力字段。

## 验证

pi-ai 探针测试断言 OpenAI 兼容请求携带十六 token 的输出上限。“模型与中转站”组件测试断言普通及带方括号前缀的 `gpt-image-*` ID 不出现在文本选择器中，同时文本模型仍可选择并显示对应说明。

## 考虑过的替代方案

**在八 token 请求被拒绝后重试。** 不采用，因为确定无效的第一次请求会浪费延迟和额度统计，而且不同中转站的错误没有统一的最小值错误码。

**通过生成图片测试生图模型。** 不采用，因为连接按钮会创建可能计费的图片资产，同时还需要应由生图路由持有的图片专用请求字段。

**排除 ID 中包含 `image` 的所有模型。** 不采用，因为多模态模型可以同时支持文本与图片。在模型目录没有能力声明时，只把明确的 `gpt-image-*` 家族视为纯生图模型。

## 后果

- 文本连接测试可兼容强制要求十六 token 下限的中转站。
- 探针仍是小型提供方请求，不会改变设置或 Session 历史。
- 纯生图模型不会被文本端点探针错误判定为不可用。
- 生图路由的可用性仍由图片生成验证，而不是文本连接按钮。
