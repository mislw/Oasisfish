# Agent Note: Oasisfish 持续海景

Status: implemented

[English](2026-08-29-oasisfish-persistent-seascape.md) | 中文

## 问题

Oasisfish 品牌此前只替换了小尺寸标志。空白会话、活动消息流、侧栏工具和设置面板仍像互不关联的通用界面；若把用户提供的参考截图直接作为整页背景，又会把截图中的控件和文字固定进图片。

## 决策

AppFrame 持有一张本地位图海景，并在所有应用栏位下方持续挂载。空白 Hero 组合实时本地化文案、既有品牌标记 slot，以及从用户提供的 Oasisfish 素材中提取的透明吉祥物资源。活动对话、展开侧栏、工具箱入口、详情栏和设置页使用基于主题 token 的半透明表面，共享同一海景。设置层通过 portal 挂载到 `document.body`，使其固定遮罩和面板不受侧栏 backdrop filter 影响。

吉祥物和侧栏场景只使用 CSS transform 动画；`prefers-reduced-motion` 会关闭持续运动。参考截图仅作为设计依据，不作为交付的整页背景，因此控件、文字、响应式布局和主题 token 仍由原生界面持有。

## 考虑过的替代方案

**把用户提供的截图作为应用背景。** 截图自带侧栏、控件、标签和窗口框架，会与实时界面重复，并且无法适配其他 viewport 尺寸。

**为每个页面分别制作海洋插图。** 多份资源会让空白页、对话页、工具箱和设置页之间出现明显切换，并增加重复下载。

**只在空白 Hero 上保留海洋主题。** 任务开始或设置页打开后，产品会立即失去统一识别度。

## 后果

- 一张本地打包场景会跨应用状态持续显示，不依赖网络。
- 空白 Hero 的本地化文字和工作区控件可以独立于图片更新。
- 活动内容保留专用阅读层，同时仍能看到背景场景。
- 应用栏位使用 transform 或 backdrop filter 时，设置页仍覆盖完整视口。
- 后续替换公共吉祥物或海景资源时，无需修改 slot 契约。
