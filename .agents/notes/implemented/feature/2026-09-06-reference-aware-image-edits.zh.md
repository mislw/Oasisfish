# Agent Note: 参考图感知的图片编辑

Status: implemented

[English](2026-09-06-reference-aware-image-edits.md) | 中文

## 问题

生图工具可以在对话中看到图片附件，但服务只接受文本，并始终调用生成端点。用户要求保留或修改上传设计时，链路会丢弃原始像素，只让生图模型根据文字重新构造图片。

## 决策

`image_generate` Consumer 查找最近一条包含图片的直接用户消息，并把其中全部耐久附件引用传给 `ctx.imageGeneration`。工具默认复用参考图；当目标是无关的新图片时，使用 `use_reference_images: false` 明确关闭复用。Consumer 默认对参考图请求使用高输出质量，同时允许模型选择其他已开放的质量值。

生图提供方读取被引用的附件，并以重复的 `image[]` multipart 字段发送到可配置的 `editEndpointPath`，其默认值为 `images/edits`。没有参考图的请求继续使用 JSON `images/generations` 路径。提供方不发送 `input_fidelity`：`gpt-image-2` 会自动以高保真处理图片输入，并拒绝修改该设置。该能力扩展了[默认生图模型](2026-08-28-default-image-model.zh.md)选择的辅助路由，不会切换 Session 的对话模型。

## 考虑过的替代方案

**描述上传图片后再通过文本生图。** 这种方式会在开始生成前丢失精确几何、字体、身份特征和布局，因此仅优化提示词无法可靠恢复缺失像素。

**把附件 ID 暴露为模型参数。** 模型已经在包含耐久图片块的 Session 中工作。要求模型复制不透明 ID 会增加无必要的失败情况，并把存储术语暴露到面向任务的 schema 中。

**始终复用 Session 中的所有图片。** 较早图片可能属于已完成迭代或无关请求。选择最近一条直接用户消息既保留用户当前的视觉输入，也提供明确的关闭方式。

## 后果

- 上传参考图以图片字节进入生图模型，而不是只通过文字重构。
- 纯生图请求保留现有 JSON 请求和端点行为。
- 参考图会增加图片输入 token 成本，高输出质量可能增加费用和延迟。
- 蒙版、变体、背景控制和输出格式选择仍不属于该操作。
