# Agent Note: 非阻塞模型配置

Status: implemented

[English](2026-08-29-nonblocking-model-setup.md) | 中文

## 问题

首次启动的凭据弹窗会在用户查看工作区或理解模型路由归属之前接管应用。它还重复了“模型与中转站”已经持有的提供方编辑器，使模型配置出现两个上下文不同的入口。

## 决策

只有版本化内测声明参与 `settings.onboarding`。提供方、中转站、模型和凭据配置统一保留在“模型与中转站”。

普通会话的模型目录完成加载且没有可选项时，composer 的模型触发器会标明尚未配置。其模型面板会引导用户前往“模型与中转站”，但不会让应用根节点进入 inert 状态。既有 `session.models.routable` 规则仍独立决定 composer 输入框能否提交请求。

## 考虑过的替代方案

**保留凭据弹窗并增加设置页链接。** 这仍会阻塞首次使用，并保留两条配置路径。

**内测声明完成后自动打开“模型与中转站”。** 自动跳转仍会打断用户选择的流程，并让凭据缺失看起来像应用故障。

**把所有不可路由会话都视为尚未配置。** 已配置路由也可能暂时不可用，而空目录才明确表示没有模型可选；既有可路由性阻塞继续使用独立故障文案。

## 后果

- 缺少 API Key 不会产生启动接管弹窗。
- 模型目录为空时，composer 会持续提供本地化的设置入口提示。
- 提供方密钥继续通过设置页的只写凭据流程保存。
- 内测声明保留版本化确认和阻塞式展示。
