# Agent Note: Generated-image Tool result preview

Status: implemented

English | [中文](2026-08-29-generated-image-tool-result-preview.zh.md)

## Problem

The `image_generate` Tool stores generated bytes as a durable attachment and logs an `image` result block, but the generic Tool card flattens every non-text block to JSON. The Session therefore retains the image while the conversation shows only attachment metadata.

## Decision

The attachment presentation plugin owns the keyed `image_generate` entry in `tool.call.toolview`. Its compact row derives the prompt and lifecycle state from the logged call/result slice, filters settled `image` blocks, and renders them through the existing `ImageGallery`, retry control, and `ImageLightbox`.

The registration injects a loader bound to the owning Session id. `ConversationController.resolveImage` is part of the outward conversation service and remains the single browser URL cache and authorized attachment-read path for message images and generated Tool results. A reopened Session reconstructs the same preview from the persisted attachment reference and bytes.

## Alternatives considered

**Teach the generic Tool card to render every image block.** Generic Tool presentation does not own attachment authorization or image interaction, and treating every future non-text block as an image would weaken its open result-block behavior.

**Copy the generated bytes into an assistant message.** This duplicates durable content, changes the model-visible transcript, and makes display depend on a follow-up model response instead of the Tool result that owns the image.

## Consequences

- Generated images appear inline immediately after Tool settlement and remain available after reopening the Session.
- Attachment read failures stay local to the thumbnail and can be retried without rerunning image generation.
- Clicking a generated thumbnail uses the same original-image lightbox as user and assistant message images.
- Other Tool results retain the generic JSON fallback for non-text blocks unless their own keyed renderer claims them.
