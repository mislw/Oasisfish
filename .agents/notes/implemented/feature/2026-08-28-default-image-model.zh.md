# Agent Note: 默认生图模型

Status: implemented

[English](2026-08-28-default-image-model.md) | 中文

## 问题

对话模型可以理解生图请求，但只有组装后的 Agent 具备可调用的生图能力时才能真正产出图片。把整个 Session 切换为生图模型还会丢失当前编码/对话路由，并混合两个相互独立的提供方职责。

## 决策

生图是辅助能力，不是对话模型切换。Host 持有一个 `imageGeneration` 服务，其实时设置选择一条主提供方路由和一条可选备用路由，每条路由分别包含模型 ID 和相对图片端点。Agent 预设按需装配 `image_generate` Consumer，生成图片在工具结果进入会话日志前先通过现有附件服务提交。

OpenAI-compatible 提供方复用 `llm-pi-ai` 路由配置和凭证引用。API Key 仍保存在凭证服务中，一个自定义中转站可以同时服务对话和生图请求而无需复制密钥。该路由必须显式提供 Base URL，因为生图提供方不依赖 pi-ai 私有的目录端点解析。

提供方支持 OpenAI-compatible Images API 响应，以及包含 Markdown 图片 Data URL 的 chat-completions 响应。chat-completions 路由请求文本与图片模态并用于纯文本生图；参考图编辑仍使用 Images API 路由。

提供方请求失败时，会在可用时附带长度受限的标准 JSON 错误消息。详情进入工具结果前会统一空白并隐藏解析出的 API Key；任意响应正文不会显示。

主路由非取消失败后，如果已配置备用路由，就会尝试一次备用路由。第一条成功路由决定返回的提供方/模型标识，图片只持久化一次。两条路由都失败时报告备用错误，因为它描述最后实际尝试的路由。`image_generate` 成功结果包含“已生成。”和耐久图片，随后直接结束本轮，不再请求对话模型。

## 考虑过的替代方案

**识别到生图意图时切换 Session 模型。** 这会把生图与对话路由耦合，使后续编码对话继续使用错误模型，并要求在 Agent Loop 中增加意图拦截。

**在生图设置中另存一份 Base URL 和 API Key。** 这会复制提供方配置，并可能产生过期端点或凭证。复用现有提供方路由可让连接与鉴权信息只有一个来源。

**重试同一路由或自动选择任意已公布生图模型。** 这会掩盖实际消耗哪条凭据和配额。一条显式备用路由使选择保持确定并由用户配置。

**把已加载 Skill 当作生图实现。** Skill 可以描述何时以及如何生图，但没有已注册的可调用工具和提供方时无法产出图片字节。

## 后果

- 新任务保持所选对话模型，生图请求使用独立配置的默认生图模型。
- 模型意图仍通过正常工具选择处理，无需关键词拦截器或 Agent Loop 改动。
- 工具结果携带耐久图片附件引用，重放和现有图片渲染器可以读取同一份字节。
- 部署可以选择一条确定的备用路由，而无需切换对话模型或复制凭据；取消的请求不会启动备用尝试。
- 生图成功后停在工具结果，避免图片已经存储后又因第二次模型收尾请求失败而把整轮显示成失败。
- 提供方支持一张 OpenAI-compatible 生成结果，包括 Images API Base64、HTTP(S) URL 或 chat-completions Markdown 图片 Data URL。[参考图感知的图片编辑](2026-09-06-reference-aware-image-edits.zh.md)说明直接用户图片如何进入 Images API 编辑请求；chat-completions 参考图编辑、蒙版和变体仍是后续独立能力。
