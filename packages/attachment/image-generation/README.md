# @deepseek-ai/dsh-image-generation

English | [中文](README.zh.md)

Host-owned generated-image capability for auxiliary OpenAI-compatible Images API routes. The `image-generation` settings namespace stores `provider`, `model`, `endpointPath`, and `editEndpointPath`; execution resolves the selected route from `llm-pi-ai`, resolves its credential through `ctx.credentials`, and calls either text generation or reference-image editing. It accepts a Base64 image or HTTP(S) URL response, validates the raster signature, and persists the result through `ctx.attachments`.

## Config

| Key | Default | Meaning |
|---|---|---|
| `provider` | empty | Initial provider route; the Models settings page normally writes it. |
| `model` | empty | Initial image model id. |
| `endpointPath` | `images/generations` | Relative path appended below the provider Base URL. |
| `editEndpointPath` | `images/edits` | Relative path used when a request includes reference images. |
| `maxResponseBytes` | `25000000` | Maximum Images API JSON body or downloaded image body. |

## Model Experience

### Tool result attachment

#### What the model sees

This Host service contributes no prompt or schema of its own. Through the `image_generate` Consumer, the model sees one text result naming the auxiliary provider/model followed by the generated image block. Generated bytes stay outside the session log; the block carries a durable attachment reference.

#### Token effect

The text result is data-dependent and retained until compaction. The image contributes the selected model adapter's image-token cost when later requests include it.

#### KV Cache effect

Append-only. The new tool result follows the reusable request prefix; later provider image projection may change only the affected suffix.

## Known Limitations and Deferred Work

- Each request returns one image. Reference-image requests send every supplied image to `POST /images/edits` without a mask; variation, mask, background, and output-format controls are not exposed.
- A selected route must have an explicit `baseURL` in `llm-pi-ai`; catalog-only routes whose endpoint is implicit are not resolved by this provider.
