# @deepseek-ai/dsh-image-generation

English | [中文](README.zh.md)

## Summary

Generate one or more image candidates through a configured OpenAI-compatible route and save every successful result as a durable attachment. Each candidate tries the primary route, then one optional fallback after a non-cancellation provider failure. Images API routes support generation and reference-image editing; a `chat/completions` route supports generated Markdown image Data URLs. Provider response text, credentials, prompts, and reference bytes stay out of diagnostics; the service appends no session events.

## Use this package

Mount this plugin when a composition needs an auxiliary image route whose successful bytes become ordinary durable attachments.

### When to choose it

Choose this package when the provider exposes an OpenAI-compatible Images API or returns one Markdown-embedded image Data URL from `chat/completions`. The composition must also mount settings, credentials or launch-environment resolution, and an attachment provider. Avoid it when generated bytes must remain provider-owned or when the route requires provider-specific controls outside this package's request fields.

### Minimal configuration

Mount the plugin after the packages that provide `ctx.settings` and `ctx.attachments`, and select a route declared in the `llm-pi-ai` provider settings.

```yaml
- name: '@deepseek-ai/dsh-image-generation'
  config:
    provider: relay
    model: gpt-image-1
```

| Field | Default | Meaning |
|---|---|---|
| `provider` | empty | Initial primary provider route; the live settings section may replace it |
| `model` | empty | Initial primary image model id |
| `endpointPath` | `images/generations` | Primary generation path; `chat/completions` selects Markdown Data URL decoding |
| `editEndpointPath` | `images/edits` | Primary path used when references are present |
| `fallbackProvider` | empty | Optional provider tried after a non-cancellation primary failure |
| `fallbackModel` | empty | Model paired with `fallbackProvider` |
| `fallbackEndpointPath` | `images/generations` | Fallback generation path |
| `fallbackEditEndpointPath` | `images/edits` | Fallback reference-edit path |
| `maxResponseBytes` | `25000000` | Maximum provider JSON body or downloaded image body |

The generated [configuration catalog](../../../docs/config-catalog.md#deepseek-aidsh-image-generation) is the exhaustive source for every accepted field and its JSDoc.

### Generation and fallback

A request may launch several candidates independently. Each candidate sends the shared prompt plus its optional variation to the primary route and tries the configured fallback only after a non-cancellation generation failure. Partial success is retained in candidate order. Cancellation stops fallback; a durable attachment commit failure is returned directly and never starts another provider request.

### Reference images and durable results

An Images API route reads every supplied durable reference through `ctx.attachments` and sends multipart data to its edit path. A successful provider response is decoded, its raster type is verified, and `saveImage` must finish before the candidate appears in the returned batch. Provider and model identity accompany each committed reference. An HTTP image URL is downloaded under the same byte limit; only HTTP and HTTPS URLs are accepted.

### What can go wrong

Generation fails when the selected route is missing, has no Base URL or credential, returns an unsupported response, exceeds the byte limit, or produces bytes with an unsupported raster signature. Provider HTTP failures expose a stable error code and status summary only. Exhausting every candidate route rejects the request; mixed candidate outcomes return the committed images and a failed count.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The service installs the `image-generation` settings section and resolves the current selection for every call. Candidate tasks share no provider state and settle together; each task commits its own bytes before the batch collects fulfilled results. Provider adapters remain private helpers so fallback policy, cancellation, and attachment publication stay in the service.

| File | Role |
|---|---|
| [`src/index.ts`](src/index.ts) | Service, live settings, route execution, fallback, cancellation, and attachment commit |
| [`src/openai-compatible.ts`](src/openai-compatible.ts) | Endpoint resolution, response decoding, URL checks, and raster signature detection |
| — | No runtime invariant companion is published; route selection and attachment publication are enforced inside one service operation and have no independently diverging observation. |

</details>

<a id="model-experience"></a>
## Model Experience

### Tool result attachment

#### What the model sees

This Host service contributes no prompt or schema by itself. Through the `image_generate` Consumer, the model-visible result contains `已生成 N 个方案，请选择。` followed by every committed image block. Generated bytes stay outside the session log; each block carries a durable attachment reference.

#### Token effect

The fixed text result remains until compaction. A later request that includes a generated image incurs the selected model adapter's image-token cost.

#### KV Cache effect

Append-only. The tool result follows the reusable request prefix; later image projection changes only the affected suffix.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

These limits describe the provider-neutral controls this service currently supports.

- **Reference editing requires an Images API route** — all references are sent to the edit path without a mask; `chat/completions` rejects references, size, and quality controls.
- **Routes need an explicit Base URL** — provider catalog entries whose endpoint is implicit are not resolved.
- **Provider-specific controls are absent** — masks, backgrounds, output formats, seeds, and other proprietary fields are not exposed.
