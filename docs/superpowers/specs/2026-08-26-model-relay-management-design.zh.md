# 模型与中转站管理设计

[English](2026-08-26-model-relay-management-design.md) | 中文

## 目标

DeepSeek Harness 提供一个独立的“模型与中转站”页面，用户可以配置 API 提供方、验证提供方和模型，并选择新任务使用的默认路由。该页面只管理 Harness 配置，不读取或写入 Codex、Claude Code 或其他产品的配置文件。

## 产品流程

应用导航增加“模型与中转站”按钮。点击后打开完整设置页面，不使用弹窗或外部管理器。页面首先显示当前默认提供方和模型，然后显示已保存的提供方列表及一个编辑面板。

用户可以添加提供方，填写显示名称、Base URL、API 协议、API Key 和模型列表，然后保存并测试配置。编辑器可以从草稿中的 OpenAI 兼容端点获取模型列表；无法发现模型时，用户仍可手动添加。已保存的提供方可以编辑、删除、重新测试或设为默认路由。

首个版本支持在已保存提供方之间手动切换，不提供轮转、负载均衡或自动故障转移。

## 导航与页面布局

客户端外壳负责导航按钮，并将其连接到现有设置组合。模型设置插件负责页面内容，从而保留插件架构，避免产生桌面版独有的配置行为。

页面包含三个工作区域：

- 紧凑的默认路由控件，显示新任务使用的提供方、模型和推理强度。
- 提供方列表，显示名称、端点主机、协议、凭据状态、模型数量和测试状态。
- 提供方编辑器，负责连接字段、模型发现、手动模型编辑、保存、测试、默认选择和删除。

同一时间只打开一个提供方编辑器。提供方行使用明确的命令按钮，不依赖隐含的整行点击行为。

## 提供方配置

现有 `llm-pi-ai` 设置命名空间继续管理自定义提供方档案。每个档案保存路由 ID、显示名称、`baseURL`、API 协议和模型描述。页面使用当前 settings mutation API、revision 检查和 adapter 验证，不增加第二套提供方数据库。

API Key 继续使用只写凭据。浏览器通过 `credentials.set` 写入新密钥；settings 只保存凭据引用。重新加载表单时只显示凭据是否已配置，绝不返回或展示密钥内容。编辑连接信息时将密钥输入框留空，会保留已存密钥。

保存有效档案后，动态 LLM adapter 无需重启桌面应用即可更新。保存操作不会自动将该档案设为默认。

## 默认模型与当前任务切换

共享的 `agent-default-model` 设置命名空间管理默认提供方、模型和可选推理强度。只有在提供方和模型成功解析后，“设为默认”才会写入选择。

新任务读取更新后的默认值。已有任务保留自己的模型路由，因为请求历史和工具工作可能已经依赖当前模型。现有模型选择器继续作为切换已有任务的明确入口。

如果已保存的默认值被删除或无法解析，页面报告无效选择并要求用户选择另一个默认值，不会静默切换到无关提供方。

## 模型发现与连接测试

“获取模型”使用现有提供方发现操作，并读取编辑器当前显示的 Base URL 和尚未保存的凭据。发现结果先供用户选择，绝不覆盖用户手动修正的模型信息。

“测试连接”使用所选协议和模型发送一次真实的最小请求。Host 负责请求，浏览器不实现提供方协议。测试读取草稿端点和密钥，使用有限超时，请求简短且确定的文本响应，并按端点可达性、鉴权、协议兼容性、模型可用性和响应完成状态返回结构化结果。

测试结果只用于面向用户的诊断，不写入任务 Session，不修改默认路由，也不暴露响应头、凭据或可能含有敏感数据的原始提供方响应。界面明确说明成功测试可能消耗少量提供方额度。

## 失败处理

字段验证在写入设置前指出需要修正的提供方、端点、协议或模型。settings revision 冲突保留草稿并要求用户重新加载当前值。凭据写入失败会区分已保存档案与未保存密钥，使用户无需重建提供方即可重试。

模型发现和连接测试失败显示在编辑器旁边，并继续允许手动输入模型。删除提供方需要确认；默认提供方必须先切换到其他档案后才能删除。传输错误会转换为简短诊断，且不存储密钥内容。

## 验证

单元测试覆盖提供方表单验证、密钥保留、默认选择、删除限制、测试结果转换和草稿测试请求。真实组合测试启动发行版 Web profile，通过 settings 和 credentials API 创建提供方，连接本地 OpenAI 兼容服务器进行测试，设为默认，并验证新任务解析到选定路由。

浏览器测试覆盖导航、创建提供方、发现模型、连接测试成功与失败、默认切换、刷新后持久化及窄桌面布局。面向用户的流程通过可运行测试应用生成无密钥快照。发行验证重新构建 Windows 桌面安装包，并确认安装版能够打开该页面、保存提供方，以及重启后继续使用所选默认值。

## 已考虑的替代方案

**独立桌面管理器。** 第二套 Electron 控制层会重复 settings、凭据处理和运行时同步，同时导致浏览器部署与桌面版行为不同。

**导入 Codex++ 提供方管理器。** 它面向 Codex 配置文件，许可证和运行架构也不同。DeepSeek Harness 通过自身 settings、credentials 和 LLM 扩展点实现相同产品概念。

**自动中转站轮转。** 轮转需要请求亲和性、健康策略、重试归属和持久诊断。手动切换可以满足当前需求，也不会引入用户未要求的路由行为。
