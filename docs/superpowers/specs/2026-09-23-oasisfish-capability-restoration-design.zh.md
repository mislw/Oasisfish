# Oasisfish 能力恢复设计

[English](2026-09-23-oasisfish-capability-restoration-design.md) | 中文

## 目标

官方 Oasisfish 桌面应用在当前桌面架构上恢复已发布的默认模型偏好、本地 Skill 检索、原生记忆、辅助图片生成和图片优化能力。恢复后的能力保留已发布用户数据与可观察行为，同时保留当前自动更新器、Oasis UI 工作流、Codex 桥接、内置 Oasis Wiki 和 Wallpaper Engine 集成。

## 范围

本次交付从 `v1.20260912.4` 产品线和已完成的本地图片优化实现中恢复五项可独立测试的能力。每项能力使用当前 Cordis 服务、设置、Session 日志、附件存储、Profile 组合和桌面打包，而不是导入早期应用树。

本次交付不合并历史分支，不恢复已被取代的桌面启动代码，不替换当前自动更新器，不修改 Agent Loop，不增加隐式意图拦截器，不把本地语料发送给远程模型，也不在普通非桌面 Profile 中启用这些产品专属默认能力。

## 集成策略

实现从隔离工作树中的 `codex/release-v1.20260923.1` 开始。历史源码提供行为、公开类型、已发布存储声明、测试和文档证据。只有当历史文件的职责与依赖仍符合当前仓库时才直接复制；否则在当前职责所有者中向前移植同一行为。

每项能力以独立的评审提交落地，并带有自身行为测试和组合证据。最终组合提交在官方桌面 Profile 和选定的 Oasisfish Agent 预设中启用恢复后的包，不改变通用 Web、Headless、SDK、SDK Minimal 或 ACP 默认配置。

## 组件职责

| 能力 | 服务定义 | Provider | Consumer 与 UI |
|---|---|---|---|
| 默认模型偏好 | 现有 `agentDefaultModel` 服务 | 现有设置支持实现 | 模型设置页与当前会话模型操作 |
| 本地 Skill 检索 | `skill-search` | `skill-search-local` | `skill_search` 工具 |
| 原生记忆 | `memory` | `memory-local` | `memory_manage` 工具与记忆设置页 |
| 辅助图片生成 | `image-generation` | OpenAI 兼容路由适配器 | `image_generate` 工具、模型设置与附件结果视图 |
| 图片优化 | `image-optimizer` | 离线提示库 Provider | `image_optimize` 工具与图片生成 Skill |

## 默认模型偏好

模型设置页读取当前模型目录和完整默认选择。用户可选择 Provider、模型和受支持的推理强度，然后通过当前 Host API 保存完整 `{ provider, model, reasoningEffort? }` 值。省略推理强度会清除已保存的强度。

已有持久请求头的 Session 保留其记录选择。空白 Session 和新建 Agent 第一次解析路由时读取实时默认值。已选择的 Provider 可以服务其建议目录中未列出的模型，但 UI 只提供当前目录中的模型。当某个 Provider 持有默认值时，仍禁止删除其配置。

## 本地 Skill 检索

`skill-search` 服务负责语料声明、已加载 Skill 解析、Provider 选择、取消和结构化失败。桌面只声明内置 Oasis Wiki 和图片生成指导中的已评审语料根目录；服务不会隐式扫描每个 Skill 资源。

本地 Provider 将发现限制在已加载 Skill 的资源根目录内，按标题上下文切分支持的文本，以事务方式构建词法与嵌入索引，并在应用拥有的可变存储中持久化兼容的 SQLite 缓存。固定的本地嵌入模型打包在签名桌面资源中，通过清单和哈希校验，运行时绝不下载。

显式 `skill_search` 工具通过普通工具事件返回有界摘录、Skill 标识、相对路径和从一开始的行范围。取消或刷新失败保留最后一次已提交索引。模型资源缺失、语料无效、文件不支持或超出配置限制时明确失败，不会把源码或查询文本发送给模型 Provider。

## 原生记忆

`memory` 服务接受一个 Provider，并公开用户级和项目级记录。项目标识从规范化 Session 工作目录派生；调用方不能提供项目键。记忆仍是由模型通过 `memory_manage` 明确选择，或由用户在设置中编辑的持久事实。

本地 Provider 继续以版本 `0` 打开已发布的 `native_memory` 存储域。它保留已发布的记录字段、启用状态、容量限制、重复检查、项目可见性、原子更新和敏感内容拒绝。已有记录保留原位，不需要迁移。

每轮第一次接受的步骤上，记忆 Consumer 读取有效快照。当记忆已启用且存在可见记录时，它在请求提交前注入一条带来源的用户消息。该消息进入 Session 日志，因此回放可重建每次模型可见记忆快照。禁用记忆会保留记录并停止后续注入。

## 辅助图片生成

图片生成与对话模型保持独立。模型设置选择一个主图片路由和一个可选备用路由，并使用当前 Provider 设置和凭据引用支持的显式模型 ID 与端点路径。更改图片路由不会更改 Session 对话路由。

`image_generate` 工具接受生成或受支持的参考图编辑输入，只解析当前 Agent 有权使用的直接用户图片，调用已配置 Provider，并在返回结果前通过当前附件服务提交成功的二进制文件。结果记录实际 Provider 与模型，并通过当前附件 UI 渲染。

非取消的主路由失败可以启动一次已配置备用尝试。取消绝不启动备用尝试。成功结果在工具结果处结束，不会在图片持久化后强制进行另一轮对话模型请求。

## 图片优化

`image-optimizer` 服务校验与 Provider 无关的生成、编辑或变体请求，并编译确定性的 `ImageGenerationSpec`。规格包含规范指令、已授权附件引用、精确文字、输出要求、约束、选中来源证据和警告；不包含凭据、具体执行 Provider 或本地存储路径。

离线库 Provider 从打包资源提供经过校验的模板、案例元数据、视觉风格标签和场景标签。Provider 不执行网络请求。同步资源保留来源与许可元数据，打包提示词需要明确的再分发许可。

显式 `image_optimize` 工具解析从一开始的直接用户图片序号，并返回已准备规格或结构化澄清问题。打包的图片生成 Skill 指导模型在结构化准备有用时先调用 `image_optimize`，再调用 `image_generate`。优化器不执行图片请求，也不拦截普通轮次。

## 组合与打包

只有当所有已发布 Profile 已拥有所需依赖和行为时，共享服务定义与模型可见工具才进入 `dsh-base`。产品专属 Provider、语料、本地模型资源、Client 设置包和默认 Agent 预设启用仍由桌面或 Oasisfish Profile 提供。仅当 SDK Minimal 的包约定已经明确需要某项能力时，才向其加入对应组件。

桌面运行时打包所有新增工作区依赖、本地嵌入模型、提示库资源和生成的 Client 模块，运行时无需安装。Profile 准备通过当前 Bundle 与解析器清单加入恢复后的官方包。现有桌面恢复操作继续能够禁用可选产品 Bundle，而不禁用核心应用。

## 持久化与兼容性

恢复后的记忆 Provider 使用已发布的存储域名称和版本，不改变其存储类型。任何必要的实现适配器都围绕该声明工作，而不重写已提交数据。未来存储类型变化需要版本命名的后继和仓库持久化确认流程。

Skill 索引和生成缓存是可重建产物，不是用户记录。缓存兼容性使用明确的模型、分词器、语料和索引格式标识；不兼容缓存仅在成功重建后原子替换。附件与 Session 日志保持当前格式，因为恢复后的模型可见行为使用现有消息、工具和附件记录。

当省略具有清除含义时，设置写入保留完整选择。新设置命名空间使用当前设置校验，凭据继续留在凭据服务中。API 密钥、提示语料、记忆内容或附件字节序列不会被复制到无关配置或诊断中。

## 失败行为

| 条件 | 必需行为 |
|---|---|
| 默认路由没有服务 | 提示提交报告模型不可用；不会用静默备用改变默认值 |
| 本地 Skill 模型或语料无效 | `skill_search` 明确失败，不下载或披露内容 |
| 记忆 Provider 缺失或重复 | 记忆激活或操作以稳定记忆错误失败 |
| 项目记忆没有工作目录 | 操作以 `MEMORY_PROJECT_UNAVAILABLE` 失败 |
| 记忆内容类似秘密或超出限制 | 写入失败，且不回显被拒绝的敏感内容 |
| 图片主路由失败 | 仅非取消失败可以运行一次已配置备用尝试 |
| 图片字节无法持久化 | 工具失败且不报告图片成功 |
| 优化器需要精确文字澄清 | 工具返回结构化问题且不返回可执行规格 |
| 签名运行时缺少桌面资源 | 打包或打包冒烟在发布接受前失败 |

## 测试

每项能力采用测试驱动实现，并针对公开操作、校验、取消、释放和失败代码编写聚焦单元测试。Provider 注册表证明其 effect 可以解除。并发测试拥有各自的临时目录、数据库、端口、进程和环境变更。

真实 Loader 组合测试启动受影响的 Profile 配置，而不是只挂载手工构造的 Context。无密钥 Session 快照覆盖记忆注入、`memory_manage`、`skill_search`、`image_optimize` 和 `image_generate` 结果。Client 测试覆盖本地化设置、完整选择写入、项目可见性、路由失败、附件渲染和释放。

桌面暂存测试校验包集合、解析器清单、本地模型哈希、提示库资源和生成的 Client 模块。打包 Windows 冒烟启动真实桌面 Profile，搜索内置语料，使用相同索引和记忆存储重启，执行基于 Fixture 的图片优化与生成，并确认当前自动更新器和 Wallpaper Engine Bundle 仍可激活。

聚焦检查遵循 `dsh-pre-push-checks`。文档改动运行翻译配对、快速文档检查和 `doc-sync`；包改动运行对应的类型检查、测试、快照和构建冒烟。除非发现的依赖使改动无法缩小到局部范围，否则完整仓库测试仍由 CI 负责。

## 交付顺序

1. 在现有服务和 Host 操作上恢复默认模型设置 UI。
2. 恢复本地 Skill 检索、打包模型、显式语料和 `skill_search` 组合。
3. 恢复原生记忆、已发布存储声明、工具、设置 UI 和 Session 快照覆盖。
4. 恢复辅助图片生成、路由设置、附件结果渲染和参考图处理。
5. 集成图片优化、离线库资源、`image_optimize` 和生成 Skill。
6. 启用完整 Oasisfish 组合，运行打包验证并记录产品可见工作流。

每个顺序项以可独立通过测试的评审提交结束。后续项只消费早期项的公开接口，不访问其私有实现。

## 备选方案

合并历史产品分支可以快速恢复文件，但也会在大规模分叉历史中重新引入已被取代的桌面启动、Client 组合和持久化实现。本设计拒绝历史合并，选择保持行为的向前移植。

把所有恢复代码挂载到一个兼容 Bundle 可以隔离差异，但会在当前一方包旁重复设置、路由和生命周期职责。本设计按能力保留包职责，只使用桌面组合启用产品专属部分。

只恢复记忆和默认模型选择器可以减少首次交付，但会让 Oasis UI 工作流缺少其提示依赖的本地检索、优化和生成能力。已批准范围以可独立评审的阶段恢复完整依赖链。

## 验收条件

- 模型设置可以保存完整默认 Provider、模型和可选推理强度，新建或空白 Session 能观察到已保存默认值。
- 官方桌面在干净安装和重启后都能本地搜索声明的 Oasis Wiki 与图片指导语料，且无需联网下载模型。
- 已发布的 `native_memory` 版本 `0` 记录保持可读写；已启用的可见记录每轮一次进入持久请求历史。
- 用户和模型可通过授权 UI 或工具路径添加、更新、删除、启用和禁用记忆，并强制执行用户与项目可见性。
- 图片生成使用独立选择的路由，把成功输出保存为持久附件，并且最多执行一次已配置的非取消备用尝试。
- 图片优化从已授权引用和打包离线指导生成确定性可执行规格或结构化澄清问题。
- 当前自动更新器、Oasis UI 工作流、Codex 桥接、内置 Oasis Wiki 和 Wallpaper Engine 集成保留现有激活与恢复行为。
- 普通非桌面 Profile 默认配置不会获得 Oasisfish 专属 Provider、语料、资源或 UI 启用。
- 聚焦单元、组合、快照、文档和桌面打包检查能拒绝资源缺失、持久化回归、未释放注册、未记录模型上下文和损坏的恢复工作流。
