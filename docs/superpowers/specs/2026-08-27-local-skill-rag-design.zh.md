# 本地 Skill RAG 设计

[English](2026-08-27-local-skill-rag-design.md) | 中文

## 目标

DeepSeek Harness 为目录型 Skill 中的知识提供本地检索增强生成流程。Windows 桌面发行版默认为内置 `oasis-wiki` Skill 启用该能力，不需要另行安装运行环境、联网下载、Embedding 端点或提供方凭据。

首版通过面向模型的 `skill_search` 工具检索原文片段。它不会自动注入检索内容，不修改 agent loop，也不会把 Skill 内容发送给中转站。

## 能力角色

实现在 Skill 家族中增加三个插件角色，不将检索逻辑写入 agent loop。

- `skill-search` 定义 `ctx.skillSearch`、提供方注册表、语料解析、查询与结果类型、取消语义和提供方选择。
- `skill-search-local` 提供目录索引、本地 Embedding、混合检索和持久化索引。
- `tool-skill-search` 注册面向模型的 `skill_search` 工具，并根据 `ctx.skillSearch` 结果渲染来源位置和摘录。

检索服务使用调用会话的工作目录和作用域，通过 `ctx.skills.get()` 解析 Skill。提供方接收已解析定义，并且可以只接受自己理解的资源基址。本地提供方只接受目录资源；URL 或不透明资源会返回明确诊断，不会退化为无关的搜索方式。

## 语料声明

检索必须显式启用。本地语料规格包含 Skill 名称、相对根目录、允许的文件扩展名、字节上限和分块上限。每个根目录在 realpath 校验后必须仍位于 Skill 的目录资源基址内；绝对路径、父级穿越和符号链接越界均被拒绝。

桌面组合为 `oasis-wiki` 声明 `references` 根目录及 `.md`、`.txt` 扩展名。内置 Skill 快照继续与记录的上游 revision 逐字节一致。服务也为未来的 Skill 定义保留类型化语料声明，但绝不会隐式索引所有资源目录。

脚本、测试、美术资源、凭据和项目文件不在 Oasis Wiki 语料中，因为声明的根目录不会触及这些内容。用户或部署可通过 Cordis 配置注册其他 Skill 语料，无需修改检索工具。

## 分块与来源身份

Markdown 文件按标题层级、段落边界、列表、表格和围栏代码块分割。分块目标长度为 800 个 Unicode 码点；为保持单个围栏代码块完整，最大可增长到 1,200 个码点。普通文本分块最多保留前一分块 120 个码点的重叠。纯文本文件使用段落和行边界，并采用相同的目标与重叠上限。

每个分块记录 Skill 名称、语料 revision、规范化相对路径、标题链、从 1 开始的起止行、内容哈希和原文。分块 ID 由规范化路径、行区间和内容哈希派生，因此未改变的原文片段在增量索引中保持身份。

Embedding 输入在分块原文前加上来源标题和标题链。返回给模型的摘录始终是原始文本，不包含仅供分词使用的内容。

## 本地 Embedding

本地提供方通过受维护的 Transformers.js 运行时使用锁定 revision 的量化 `bge-small-zh-v1.5` ONNX 快照。桌面构建会把 tokenizer、模型、配置、许可证、上游 revision 和文件哈希放入不可变的应用资源。运行时只允许本地加载；模型缺失或哈希不匹配时拒绝启动，绝不会从网络下载。

Embedding 使用已归一化的 `Float32Array`。文档按有限批次计算，每个查询只计算一次。测试通过同一 Embedding 接口使用确定性 fixture 实现；桌面 staging 和冒烟验证必须运行打包后的 ONNX 模型。

## 持久化索引

本地提供方在 Harness 缓存目录下管理一个 SQLite 数据库。单调递增的 schema version 覆盖语料元数据、源文档、分块、FTS 记录、向量和模型身份。向量以小端序浮点 BLOB 存储。语料键包含 Skill 提供方、Skill 名称、已解析资源根目录、语料规格摘要和 Embedding 模型 revision，防止某个安装或模型复用不兼容的索引。

中文词法检索会把 Latin 单词以及 CJK 单字和双字词组成规范化 token 流，并存入 SQLite FTS5。原始文本独立保存。提供方加载时检查 SQLite 和 FTS5 可用性；支持缺失属于配置错误，必须立即失败。

第一次查询会构建缺失的语料索引。后续查询会先比较文件大小、修改时间和 SHA-256，再替换变更文档。文件删除时同步删除分块。完整变更批次的 Embedding 和 FTS 记录成功后才在同一事务中提交，因此取消、解析错误或模型失败会保留最后一份完整索引。

同一语料的刷新由一个进程内锁串行化。调用取消会终止目录扫描、Embedding 批次和查询工作。插件释放必须等待活动工作停止，再关闭数据库和模型运行时。

## 检索与重排

每个查询产生两个有上限的候选列表：SQLite FTS5 BM25 结果和已归一化向量的余弦相似度结果。Oasis Wiki 语料规模允许在进程内精确计算所有向量；语料超出已配置的分块或字节上限时，提供方必须拒绝执行，不会静默降级。

倒数排名融合会合并词法和语义列表。第二阶段确定性重排会提高精确标题和路径词匹配的权重，然后应用最大边际相关性减少相邻重复分块。这是混合融合重排，不是学习型 cross-encoder。默认返回 5 条结果，工具允许设置 1 到 10 条。

每条结果包含排名、融合分数、相对来源路径、标题链、行区间和原文摘录。对于未变更的索引和查询，结果顺序保持稳定。

## 面向模型的工具

`skill_search` 接收 `name`、`query` 和可选 `limit`。工具验证选中 Skill 允许模型调用，在调用 agent 的作用域中解析 Skill，然后交给 `ctx.skillSearch`。它的展示意图为 `locations`：调用显示 Skill 和查询，结果显示各条来源位置和摘录，不暴露绝对安装路径或索引内部信息。

完整工具调用和结果是普通的持久 Session 事件，因此所有进入后续模型请求的片段都能从日志重建。工具不增加合成上下文消息。工具引导要求模型先加载 Skill，再为事实或 API 问题搜索已声明语料，并在答案中引用返回的相对路径和行区间。

检索为空是成功结果，它会标明已搜索的 Skill，并建议更精确的词或同义词。未知 Skill、禁止模型调用的 Skill、未声明语料、源文件无法读取、索引超限、模型失败和取消必须保持为不同的结构化错误。

## 桌面打包

桌面监督进程通过子进程环境变量提供不可变模型路径、内置 Skill 路径和可变缓存路径。打包后的应用包含 Windows x64 下模型和原生运行时需要的全部文件。它不修改全局 `PATH`，不安装 Python 包，也不把模型放入用户 Skill 目录。

Staging 验证检查模型 manifest 与哈希、Oasis Wiki 语料声明、三个检索插件及无 reparse point。解包冒烟测试使用全新用户数据目录启动打包后的应用，加载 `oasis-wiki`，执行一次中文 `skill_search`，确认返回的所有来源位于 `references` 下，重启应用后再确认持久化索引仍可用。

## 隐私与限制

原文、分块、Embedding、词法 token 和查询文本全部保留在本机。检索插件不发起 HTTP 请求，不复用已配置的对话提供方或中转站。SQLite 文件使用桌面用户的私有应用数据目录；诊断不会打印分块文本、查询文本、凭据或 Skill 绝对路径。

首版不提供设置页、手动重建按钮、学习型重排器、近似最近邻索引、OCR、PDF 导入或远程 Skill 检索。这些功能需要单独的产品与生命周期决策。语料状态只通过日志和结构化工具错误提供。

## 验证

单元测试覆盖语料路径限制、Markdown 与文本分块、CJK 词法分词、Embedding 归一化、索引替换、取消、BM25 和向量候选生成、融合顺序、重复结果减少、结果上限和错误区分。

集成测试挂载真实 Skill 注册表、文件系统 Skill 提供方、检索服务、确定性本地检索提供方、工具注册表和 Session 日志。它们验证作用域感知的 Skill 解析、持久工具事件、相对引用、增量更新，以及刷新失败后保留最后完整索引。

无密钥可运行快照会加载 fixture Skill 并调用 `skill_search`，固定模型可见工具记录。桌面验证会运行打包后的 Embedding 模型和真实内置 Oasis Wiki 语料。发布声明前必须执行相关 typecheck、lint、build、hygiene、文档、打包和解包冒烟检查。

## 已考虑的替代方案

**由中转站提供 Embedding。** 该方案可减小安装包，但检索会依赖端点兼容性、凭据、网络、额度和新的隐私说明，与桌面版的自包含要求冲突。

**只使用词法搜索。** Ripgrep 或 BM25 适合精确 API 名称，但会错过改写句和中文表达差异。它保留为混合检索的一半，不是完整实现。

**在每次模型请求前自动检索。** 自动注入会为无关回合消耗 token，并需要新的持久上下文事件和查询选择策略。显式工具使检索保持可观测、可记录、可取消，并由当前 Skill 工作流控制。

**通用项目文档 RAG 数据库。** 索引任意工作区会引入授权、项目归属、忽略规则和删除语义，超出当前 Skill 知识库需求。首个能力仅限于已声明的 Skill 资源，同时保留可以在未来支持其他语料类型的提供方接口。
